# 词迹 AI 对话原型

独立候选原型，供评审体验。基于正式版 2.18.1 的导航、数据与听写规则，不并入正式产品，不改变应用版本、站点访问范围或用户数据。

```bash
npm ci
npx vite build --config prototypes/ai-companion/vite.config.ts
npx vite preview --config prototypes/ai-companion/vite.config.ts   # http://127.0.0.1:5179/#chat
node prototypes/ai-companion/scripts/bundle-artifact.mjs            # 打包为单文件页面，供私有托管评审
node prototypes/ai-companion/qa/flows.mjs                           # 浏览器路径检查（需先启动 preview）
node --import ./tests/register.mjs --test tests/ai-companion-prototype.test.mjs
```

示例数据从正式数据抽取：`node --import ./tests/register.mjs prototypes/ai-companion/scripts/extract-data.mjs`。

## 设计方向

AI 是学习空间里一层安静的工作面，没有另起一个应用。学习导航始终是词迹自己的；对话出现时，学习导航收成窄栏，对话列表按需从左上角展开，两条侧栏不长期并排。

- **空态**：宽屏（桌面、iPad）把「今天想学什么？」与输入框放在视觉中心，起聊建议是输入框下方一行轻量胶囊；第一条消息发出后，输入框移到底部，内容优先。手机上问候留在中部，建议与输入框贴底，靠近拇指与软键盘。理由：宽屏上居中让“定目标”成为唯一焦点；手机上输入在拇指区，键盘弹出时不跳动。
- **左上角一组操作**：对话列表、新对话、临时对话三个按钮，位于原「学习助手」标题处。空白新对话里「新对话」置灰，临时对话开启时按钮展开为「临时对话」标签。
- **右下角入口**：46px 圆形按钮，图案是品牌遗忘曲线收成一笔、末端一个蓝点（“学过的轨迹通向一个问题”），回答旁边的标记用同一图形。打开为就地小窗，可展开为完整对话，同一会话、引用、附件和草稿随之移动。
- **视觉**：冷灰、白、炭黑，一个克制的蓝色强调；正文用系统中文字体，英文原文用衬线。只有浮层（弹出菜单、小窗、对话框、右下角按钮）带阴影，其余用细线。

### 组件规则（全站同功能同规则）

| 层级 | 圆角 | 用于 |
| --- | --- | --- |
| 文字输入 | 14px | 搜索框、输入框、选择器、对话输入框；同一 1px 边线与同一焦点环 |
| 控件 | 10px | 按钮、菜单行、分段控件选项、来源附件条 |
| 卡片表面 | 18px | 计划卡、回答卡、弹出菜单 |
| 整页浮层 | 22px | 对话框、设置、小窗、手机底部弹层 |
| 圆形 | 50% | 图标按钮、起聊建议、右下角入口 |

焦点统一为 2px 强调色描边或 3px 半透明焦点环；悬停反馈只在支持悬停的指针设备上出现，触控点按后不残留。手机与 iPad 触控目标不小于 40–44px；所有动效在系统或设置中“减少动态效果”时关闭位移。

## 页面与交互

| 区域 | 说明 |
| --- | --- |
| 完整对话（`#chat`） | 左上角：对话列表 / 新对话 / 临时对话；右上角：收起为小窗回到学习页。会话标题和「回到刚才的对话」放在顶栏，切换历史后可一键返回。 |
| 对话列表 | 1280px 以上与对话并排，其余宽度为抽屉。搜索、按日期分组、示例与草稿标注、删除二次确认；底部是全站设置与对话隐私。临时对话不进入列表。 |
| 临时对话 | 不进入历史，不写入浏览器存储。离开有内容的临时对话会在页面内确认；其草稿、引用和附件一起清除。 |
| 输入框 | Enter 发送、Shift+Enter 换行（可改为 ⌘/Ctrl+Enter 发送），输入法选词时的 Enter 不发送。回答中可以继续输入，发送键变为停止键。 |
| 来源 | 「来源」菜单：添加图片、文件；开关学习记录与当前文章全文。附件条显示读取状态，点按可预览，可移除；支持拖放与粘贴图片。 |
| 回答方式 | 输入框右侧显示「自动 / 仅下一条 / 默认」与实际档位，随输入实时判断。菜单可选「仅下一条」或「后续默认」。 |
| 选文提问（`#reading`） | 选中正文后在附近出现：问问 AI、翻译、解释词义、分析语法。触控设备上工具栏放在选区下方，避开系统菜单。跨段、键盘（聚焦段落 Enter 选整段，Shift+Enter 延伸到下一段，Esc 关闭）均可用；空选区、超过 800 字符、选到正文以外都有提示。 |
| 小窗 | 桌面与 iPad 横屏打开时页面让出右侧，学习导航收成窄栏；iPad 竖屏与手机为底部弹层。 |
| 学习闭环 | 计划卡可改时间与范围 →「开始听写」进入练习 → 程序判分并解释错在哪 →「只重练错项」→「把结果带回」原会话，反馈依据真实对错。长期计划分为整段安排（草稿，加入前确认）与今天第一步。 |
| 语音会话 | 独立入口，入口提示与会话内横幅都说明未接通语音、不使用麦克风。用文字代替说话，AI 回答为字幕，可静音（系统朗读）、结束；结束后字幕与生成的卡片回到同一对话。 |
| 设置 | 全站唯一入口：常规 / 学习安排 / 对话 / 模型 / 数据与隐私 / 关于原型。手机上先列分区再进入。 |

## 演示范围

| 本地真实运行 | 演示逻辑或未接入 |
| --- | --- |
| 听写判分沿用正式产品 `lib/voice/dictation.ts` 的比对规则；错误分类用 `lib/mistakes.ts` 的编辑距离 | 回答文字：本地规则，未连接任何模型 |
| 词义来自正式词库（`public/data/v1`，稳定词条 ID 与教材来源） | 译文与语法说明：原型撰写的逐句译注，界面中标明非 NOAA 或教材内容 |
| 文章《Mangrove Forests》原文、来源与权利说明来自正式阅读数据 | 学习记录：示例数据，界面中标为示例 |
| TXT/MD/CSV 在本机读取（UTF-8，前 20,000 字）；文件中的英文词可生成听写 | 图片识别、PDF/DOCX 解析、云端上传：未接入，附件标为“仅附件” |
| 路由判断、请求组装、单次与默认选择、拒绝发送 | 语音：流程演示，不采集麦克风，不调用音频模型；AI 字幕可用系统朗读 |
| 计划拆分、草稿、引用、对话保存与清除 | 服务状态（模型不可用、额度不足、回答不完整）由设置中的“原型测试”模拟 |

存储：普通对话保存在本浏览器（文字、引用、附件名称与读取状态）；附件内容、图片预览、临时对话从不写入。清除对话会提升数据代际，正在生成的回答随之作废。

## 模型路由

| 任务 | 模型 · 推理强度 |
| --- | --- |
| 常规学习对话、状态总结、普通短计划、作文反馈、练习反馈 | Sol · 中 |
| 多约束、有步骤依赖的规划 | Sol · 高（候选；用户原话“Soda High”暂按此理解，尚未确认；设置中可改为 Sol · 中） |
| 阅读中的简单翻译、选词释义 | Terra · 低 |
| 选文语法、语境辨析 | Terra · 中 |
| 拼写核对、确定答案评分 | 程序完成，不调用模型 |
| 语音会话 | GPT-Live 1；其中的文字任务按上表委派 |
| 轻量查询 | Luna（gpt-6-luna）为后续候选，本轮未启用 |

- 判断只读用户自己的话：引用、附件、文章长度、对话轮数都不参与，引用里写着“请升级模型”不会升级。
- 「仅下一条」只影响一条实际发出的消息；空消息、被拒绝的发送不消耗它。「后续默认」写入设置，可在输入框或设置中恢复自动。
- 模型不可用或额度不足时不发送、不自动换模型重试；用户可以点选“只把这条改用某档位发送”。回答不完整时保留已收到内容，「继续回答」明确标为另一次请求。
- `buildRequest` 把路由的 model 与 effort 原样写入请求；消息下的标签从请求读回，详情里显示 `model` 与 `reasoning.effort`。

## 正式接入待办

1. **路由下沉到服务端**：`lib/assistant/core.ts` 的 `responsesPayload` 目前对 gpt-5/6 固定 `reasoning: { effort: "low" }`，模型来自用户的单一配置（默认 `gpt-6.1-terra`）。接入时由服务端按任务类型决定 model 与 effort 并写入请求，客户端只提交任务类型与单次选择；响应带回实际使用的 model/effort，界面按响应显示。提示中提到的“候选代码把 Terra 默认映射到 Sol 并固定 Sol / Medium”不在本仓库任何分支，合并该候选前需对照修正。
2. **实测**：用真实 API 确认 Sol/Terra 各档位可用组合、单价与延迟，再定预算预留（沿用 2.5 的原子预留）与“额度只够较低档位”的阈值；本原型不含任何效果或成本数据。
3. **对话存储**：按账户存入 IndexedDB，沿用现有 generation/CAS 防止清除、恢复或切换账户后的迟到写入；临时对话与附件内容不落盘；备份格式如需包含对话，按 `DATA_SCHEMA.md` 增加兼容迁移。
4. **附件**：PDF/DOCX 复用阅读导入已有的 `lib/pdf-import.ts`、`lib/docx-import.ts` 及其资源上限；图片识别需要另行确定视觉模型、隐私说明与路由，接入前保持“仅附件”。
5. **选文**：把 `selection.ts` 与阅读页的 `pointFrom` 接到 `components/studio/reading.tsx`；整篇文章开关对应 AI 设置里的“发送范围”。
6. **学习闭环**：计划卡打开现有听写与学习会话；FSRS 卡片与复习事件继续走现有事务路径，原型本身不写任何学习记录。
7. **设置合并**：在 `components/console-settings.tsx` 现有分区上调整为原型的六个分区；API 密钥仍只在服务端加密保存。
8. **全站组件规则**：把上表圆角与边线写入 `app/globals.css` 的变量（现为 control 20 / card 28 / sheet 32），逐页替换搜索框、输入框、选择器与弹层的差异。
9. **版本**：对话、选文、学习闭环作为一组功能并配套质量改进上线时为次版本（2.19.0）；此前的兼容修复按补丁版本。
