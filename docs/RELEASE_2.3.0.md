# 词迹 2.3.0

这是次版本更新，内容是性能优化、代码精简、安全加固，外加一批无障碍修复。学习功能、词条 ID、用户数据 schema `1.1.0`、备份格式、"词卡 + 事件"同事务写入、撤销和 revision 冲突保护都没有变。线上认证方式、访问范围和生产数据没有改动。

完整过程、测量方法和可复现的测试命令见 [2.3.0 优化报告](OPTIMIZATION_REPORT_2.3.0.md)。

## 性能

- `useVocabulary()` 返回稳定的对象，并只建一次共享的 `byId`。练习、记录和三种记单词模式不再各自重建 4,681 条的 Map。
- 提示条的状态移到独立 store。提示出现或消失时，重渲染的组件从 50 个减到 3 个。
- 练习界面的键盘监听只绑定一次。连续按 40 次键，新增的监听从 61 次降到 0 次。
- 标签页改用 React `<Activity>` 保持挂载。切换标签从点击到绘制，中位数由 69.5 ms 降到 45.0 ms（4 倍 CPU 节流下）。切换后，词库的搜索、页码和阅读中打开的文章都会保留。
- 阅读的查词分词结果会缓存。再次回到阅读页时，不会重新读取目录和个人文章。
- 首页初始 JS（gzip）从 124,122 B 变为 124,222 B（+100 B）。

## 精简

- CSS 删除了 233 条被后面同一选择器完全覆盖的声明，以及 55 条只针对已不存在的类名的规则。源码从 4,673 行减到 4,353 行，gzip 后从 24.7 KB 减到 24.0 KB。改动前后的 96 张截图逐像素相同。
- 删除了未使用的 `geometry` 画风和 `workloadEstimate`。
- 设置里的 AI 连接诊断拆成独立组件 `components/studio/ai-connection.tsx`，保存、测试、移除三个操作共用同一套请求处理。`console-settings.tsx` 从 819 行减到 681 行。

## 安全

- 页面带每次请求生成的 nonce CSP，另有 `frame-ancestors 'none'`、`X-Frame-Options`、`nosniff`、`Referrer-Policy`、`Permissions-Policy`、COOP，HTTPS 下还有 HSTS。私有接口一律 `no-store`，并带全禁 CSP。
- 客户端不能再通过请求头指定 vinext 使用的脚本 nonce。
- 私有同步有独立限流：每分钟 30 次，每天 200 次写入。超限返回 429，带 `Retry-After`，备份页会显示需要等待的秒数。如果部署缺少限流表，同步照常工作。
- 框架产生的 404、405 和 5xx 统一为 JSON，不带内部信息。405 带 `Allow`，502 和 504 保留原状态码。
- 身份头会拒绝网关不会发出的值。用户键的推导方式不变。新增可选开关 `IDENTITY_TRUSTED_HOSTS`，默认关闭。
- 服务端会话、密钥轮换等涉及线上身份和生产数据的方案写在 [SECURITY_PLAN.md](SECURITY_PLAN.md)，等所有者确认后再实施。

## 无障碍（修复）

- 选中态、答对状态、今日卡片次要文字等处的文字对比度全部达到 WCAG AA。浏览器审计的不达标项从 22 处降到 0。
- 系统深色加"增强对比度"时，之前设置不生效，现在生效了。
- iPad 竖屏（761–1000px）的侧栏图标下加了文字。
- 浏览器字号调大（约 150% 及以上）时，词卡的撤销按钮不再被挤出屏幕，"再看看/认识"横向排列，配对块完整显示释义。
- 系统返回手势（iOS 边缘右滑、安卓返回键）会依次关闭词条详情、设置、练习（保留续学点）、记单词模式和当前标签，回到今日页后再返回才会离开应用。离线时按返回也不会刷新页面。

## 验证

- `npm run typecheck`、`npm run lint`、`npm run test:unit`、`npm run build`、`npm run test:runtime` 全部通过。单元测试从 122 项增加到 139 项。运行时冒烟测试会检查安全头和 405 响应。
- `/code-review high` 的有效发现已处理，`/security-review` 没有发现问题。未处理项见报告。
- 截图对比、对比度、大字号、返回手势的检查脚本在 `artifacts/qa/`，性能测量脚本和结果在 `artifacts/perf/`。

## 没有验证的部分

- 没有在真实 iPhone、iPad 或安卓设备上测试。返回手势、大字号和性能数字都来自无头 Chromium（性能测量开了 4 倍 CPU 节流）。
- 没有部署到线上，也没有核实托管层是否另外加了 HSTS 等响应头。
- 静态资源不经过 Worker，所以没有这些安全头。`public/_headers` 的建议写在安全方案里，本次没有添加。
