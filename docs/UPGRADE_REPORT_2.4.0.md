# 2.4.0 更新报告

2026-09-29，基于 2.3.0（`65bd890`），分支 `claude/wizardly-faraday-yydubr`。发布摘要见 [RELEASE_2.4.0.md](RELEASE_2.4.0.md)，任务清单见 [TASKS.md](../TASKS.md)。

## 一、结论

| 方面 | 结果 |
| --- | --- |
| 性能 | 作答保存从“复制整个事件数组 + 三处全量统计”改为增量维护：5 万条事件时连续作答 200 次从约 2.0 秒降到约 21 毫秒。浏览器会申请持久化存储。 |
| AI | 八个任务接口全部有前端入口。请求附带经服务端校验的学习画像；输出上限统一为 10,000（模型上限更低时取模型上限），流式读取；有每日 token 预算和本机缓存；提示词按前缀缓存规则排列；附带评测 harness。 |
| 安全 | 已实施主密钥分版本与轮换、静态资源 `_headers`、Service Worker 消息来源校验、依赖精确锁版本。服务端会话和 CSP 报告接口评估后不做。 |
| 学习新功能 | 错因细分与易混词、练习中造句、写作与 AI 批改（版本、估分、批注、目标词、修改稿）。 |
| 兼容性 | 词条 ID 与已有学习记录不变。备份 schema `1.1.0 → 1.2.0` 只新增 `writings`，旧备份可以导入。IndexedDB 版本 `2 → 3` 只新增一个表。D1 只新增一张表（迁移 0003）。 |
| 验证 | `npm test` 通过（数据审计、类型检查、173 项单元测试、构建、Worker 运行时检查），`npm run lint` 通过。 |

## 二、改了什么

### 1. 性能与本机数据保留

- **增量复习历史**（`lib/progress.ts` 的 `ReviewHistory`）：
  - 追加事件为均摊 O(1)；撤销集合、有效复习、按日汇总和每个词的计数都随追加更新。
  - `stats(now)` 按版本和本地日期缓存。
  - `useVocabulary()` 用 `data.history` 取代 `data.events`；今日页、学习记录和外壳共用一次计算。
  - `studyStats` 和 `activeReviews` 保留，作为测试中的对照。
- **选词只算一次**：`summarizeStudy` 和 `buildStudyQueue` 可以接收外壳算好的 `selectEntries` 结果。
- **持久化存储**（`lib/persistence.ts`）：
  - 有学习记录后，或本轮第一次作答后，调用 `navigator.storage.persist()`。新用户首屏不申请。
  - “数据与备份”显示保护状态与占用空间，未受保护时提供“申请保护”按钮。
  - 未受保护且 14 天没有导出备份时，最多每 14 天提醒一次。
- **没做**：词库列表的 `content-visibility`。它导致 8/96 张截图变化，原因是行高不一致、占位高度无法匹配，每页又只有 40 行，收益小，所以放弃。

测量（Node，合成事件，含约 2% 撤销）：

| 事件数 | 首次载入 | 200 次追加 + 统计（新） | 旧方式估算（复制 + 重算） |
| --- | --- | --- | --- |
| 1 万 | 9.9 ms | 9.8 ms | 362 ms |
| 5 万 | 53.7 ms | 20.8 ms | 2,029 ms |
| 10 万 | 113.3 ms | 24.8 ms | 4,465 ms |

旧方式在应用里还要在外壳、今日页、学习记录各算一次，实际开销约为表中的 3 倍。

### 2. AI

**接口与前端入口**

| 接口 | 入口 |
| --- | --- |
| `explain`（新增 `focus: mistakes`） | 词条详情 → 讲解，可选重点 |
| `check-sentence` | 词条详情 → 造句；练习中造句 |
| `contrast-words` | 词条详情 → 辨析（推荐你答错过或拼写相近的词）；学习记录 → 容易混的词 |
| `generate-practice` | 学习记录 → 针对错题出题（可作答，不改变复习计划） |
| `review-essay`（新） | 写作 → AI 批改 |
| `mnemonic`（新） | 词条详情 → 记忆 |
| `story`（新） | 学习记录 → 读一篇短文 |
| `diagnose`（新） | 学习记录 → 学习诊断 |

**个性化（数据最小化放宽）**
- 浏览器的 `lib/learner-profile.ts` 生成学习画像：
  - 错误作答与错误类型，按 `lib/mistakes.ts` 细分；
  - 薄弱词、易混词对；
  - 最近 12 条笔记，每条最多 400 字符；
  - 近 7 天正确率、近 30 天学习天数、写作概况。
- 服务端的 `lib/assistant/profile.ts` 逐字段校验、限长，丢弃非正式词库 ID，并由服务端补上词头。
- 系统提示声明画像和作文都只是数据，不能执行其中的指令。

**保留的约束**
- API Key 加密保存。
- Base URL 校验。
- 教材范围、册次、单元和页码只能来自 `suppliedEvidence`。
- 伪称教材原句、以及词库证据里没有的页码都会被拒绝。学生自己写到的页码可以在修改稿中保留。
- 作文批注引用的原文必须能在作文里找到，否则略去并在 limitations 里说明。

**输出上限**
- `resolveMaxOutputTokens` 取三者最小值：10,000、已知模型的文档上限、设置里的单次输出上限。
  - DeepSeek V4/V4.1 的上限是 384K，所以实际为 10,000。
  - `deepseek-chat` 为 8,192。
- 为避免 10,000 token 的回答被 25 秒超时截断，改为流式读取：设置里的超时变成“无响应超时”，单次最长 5 分钟。
- 回答被截断时返回 `output_truncated`。

**费用控制**
- 本机缓存 `pep-vocab-ai-cache`：键是任务加输入，不含画像，所以画像变化不会让已保存的回答失效。标签页一打开就显示已保存的回答，重新生成需要手动点。
- 每日 token 预算：
  - 默认 20 万，按北京时间日计，请求前检查。
  - 用量取服务商返回的 `usage`；即使回答没有通过校验也计入，因为已经计费。
  - 设置页显示今日总量、缓存命中和输出。
- 前缀缓存：
  - 请求顺序为固定系统提示（约 2,400 token，八个任务共用）→ 学习画像（键序固定；同一天内新增复习不足 30 次时复用）→ 本次任务。
  - harness 的离线模式验证了九个用例共享同一前缀。
  - DeepSeek 自动缓存前缀，按 `prompt_cache_hit_tokens` 计量。
  - OpenAI 官方端点另加 `prompt_cache_key`。

**DeepSeek V4.1 Flash 的系统提示与 harness**
- 调研依据：DeepSeek API 文档（Chat Completions、Context Caching）与 V4.1 Flash 发布说明，均为搜索摘要。本环境的出站代理拦截了 api-docs.deepseek.com，无法打开原页核对。
  - 官方 API 的稳定模型名是 `deepseek-flash`；旧名 `deepseek-v4-flash` 仍然接受，由 V4.1 Flash 提供服务。
  - 输出上限 384K；非思考模式默认 8K。
  - 思考 token 计入 `max_tokens`。
  - JSON 输出需要提示词里出现 “json”。
  - 缓存按前缀单元命中。
- 据此的设计：
  - 默认仍用 `deepseek-v4-flash`。它仍被接受，也不改变你已保存的配置；设置里可以选 `deepseek-flash`。
  - 关闭 thinking，避免推理 token 挤占 10,000 的输出额度。
  - `response_format: json_object`，提示词中写明 json。
  - 各任务使用不同的 temperature：批改和检查 0.2，短文 0.9。
- 系统提示（`lib/assistant/prompt.ts`）的结构：角色 → 数据边界 → 证据规则 → 输出规则 → 八个任务各自的说明和输出形状。作文任务附带 `lib/assistant/rubric.ts` 的高考评分方法（先定档后调分，应用文和读后续写各五档，结构与难句的看法），依据见 [ESSAY_RUBRIC.md](ESSAY_RUBRIC.md)。任务说明还规定：引用原文必须逐字、目标词逐一评价、修改稿只改错不重写。
- 深度批改的输出包括档次与理由、结构与衔接、句式与难句、读后续写的衔接与情节。服务端把估分调整到所选档次的范围内，丢弃在原文中找不到的句子和衔接词。
- harness（`scripts/ai-harness.mjs`）：
  - 用例：十个，覆盖八个任务（作文有应用文和读后续写两个），并带一份真实形态的学习画像。
  - 离线模式：检查提示词构建与共享前缀，已纳入单元测试。
  - `--live` 模式：记录耗时、token、缓存命中、结束原因、是否通过生产校验，以及用例期望（例如作文至少找出 3 处问题）。

### 3. 安全（`docs/SECURITY_PLAN.md` 未实施项的评估）

| 项 | 决定 | 说明 |
| --- | --- | --- |
| B 主密钥分版本与轮换 | 已做 | 新增 `AI_CONFIG_ENCRYPTION_KEYS` 和 `_ACTIVE`，v3 密文格式为 `kid:base64`，附加验证数据中也包含 kid。不设新 Secret 时行为与 2.3.0 完全相同。旧密文在保存设置时重新加密，也会在 AI 请求成功解密后按条件更新（`WHERE encrypted_api_key = 旧值`）。 |

| D Service Worker 消息来源 | 已做 | 只处理同源页面发来的 `PREPARE_LEXICON`。 |
| E 依赖锁版本 | 已做 | 4 个依赖改为精确版本，锁文件里的解析版本不变。`npm audit --omit=dev` 为 0；完整 `npm audit` 有 4 个 moderate，都在开发工具链（undici → miniflare → wrangler），修复需要降级构建插件，记录在案。 |
| A 不依赖网关的服务端会话 | 不做 | 站点仍由网关保护且只有你使用；它需要 Passkey、新表和模式切换，风险和工作量都大，等迁移托管平台时再做。 |
| C.2 CSP Report-Only / Trusted Types | 不做 | 需要新增一个报告接口，收益低。 |
| C.3 从页面策略中去掉 `wasm-unsafe-eval` | 不做 | 需要逐项核实 pdf.js 与 Tesseract 的 WASM 加载位置，并在真实浏览器里回归。 |

新的 AI 数据面：画像按字段逐一白名单校验，并在服务端解析词头；请求体上限从 24 KB 提高到 64 KB；四个新路由已在 `PRIVATE_API_ROUTES` 登记，并纳入 401/403/413 等安全回归测试。

### 4. 学习新功能

- **错因细分**（`lib/mistakes.ts`）：每次读取时根据作答内容重新判断，不修改已存事件。
  - 编辑距离 ≤ 2 为“差一点”（4 个字母以内的词 ≤ 1）。
  - 答案是另一个词条的词头时算“混淆”。
  - 留空或词义回忆题算“想不起”。
  - 听音选择题算“没听出”。
- **练习中造句**：
  - 条件：不是本轮重练、词卡复习次数 ≥ 2，并且这题没有答错。
  - 造句记为 `questionType: sentence-output`、`skill: output` 的复习事件，走同一个“词卡 + 事件”事务。
  - AI 判定需要修改时评分记为 2，否则记为 3。
  - 事件 ID 不采用练习进度的编号格式，所以恢复练习进度时不会把它当成某一步的作答。
- **写作**（`lib/writing.ts`、`components/studio/writing/`）：
  - 目标词匹配能识别规则变化、约 70 个常见不规则形式，以及中间隔了宾语的短语。
  - 本机检查篇幅、覆盖、重复用词、长句或全是短句、句首大写和代词 I。
  - 已批改的版本不再修改，后续编辑成为新版本。
  - 示例题目和读后续写的开头都是为词迹新写的，不引用考试原题。
- **数据**：IndexedDB 新增 `writings` 表，备份 `1.2.0` 包含 `writings`，逐条校验；`1.0.0` 和 `1.1.0` 备份导入时补一个空列表。云端同步只接受当前 schema 的上传，旧版页面需要刷新后再同步。

### 5. 界面

- 写作入口采用你确认的方案 B：放在今日页“记单词”下方，导航不变。
- 前端按 frontend-design 与 apple-design 两个技能设计：
  - 沿用现有的系统字体、蓝色主色和语义色；
  - 学生自己的英文（作文、造句）和例句用阅读衬线体；
  - 唯一的标志性元素是“练习纸”：目标词写在横线上，批改用编号的红色波浪线，与右侧编号列表对应。
- 已截图检查：桌面、手机，浅色、深色；覆盖今日写作卡、设置、编辑、批改、写作记录、学习记录错因与诊断、词条 AI、设置用量、练习造句。AI 回答用本地模拟数据，没有调用真实模型。截图过程中修正了两处：

## 四、没做或没验证的

- **经典文章**：找 20–30 篇公版文章的子代理按你的要求中途停止，没有产出，仓库没有新增阅读内容。
  - 如果还要做，建议由我写一个固定清单（作品和章节范围），用脚本从 GitHub 上的 Gutenberg 镜像下载，沿用现有的来源记录流程。这样 token 成本低得多。
  - 本环境的代理拦截了 gutenberg.org，只能用 GitHub 镜像。
- **真实模型**：本环境没有你的 API Key，没有跑 `--live`。10,000 输出、流式、`usage` 字段、缓存命中率、各任务的输出质量，都需要你配置后运行一次 `HARNESS_API_KEY=... node --import ./tests/register.mjs scripts/ai-harness.mjs --live` 来确认。每个用例默认跑两次，会产生少量费用。
- **部署**：没有部署。上线前要执行 D1 迁移 0003，并确认托管层会应用 `_headers`。
- **真机**：没有在 iPhone/iPad 上验证。持久化存储在 iOS Safari 上通常只有“添加到主屏幕”后才会授予。
- **子代理设置**：你要求编码子代理用 Sonnet 5.5（extra），找文章用 Sonnet 5.5（medium）。本会话只能指定模型，不能设置推理强度，所以都按 Sonnet 默认强度运行。第一批 worktree 基于旧提交，已作废并重新派发。
- **其他**：首屏 JS 体积本轮没有重新测量（新界面都是懒加载）；AI 连接测试的少量 token 不计入每日预算。

## 五、其余 AI 功能的建议（未实施）

按你的要求，“按任务换模型”不做。其余建议按优先级排列：

1. **批改结果逐步显示**：服务端已经在流式读取，可以把进度或部分字段转发给页面，长批改不用一直等转圈。代价是需要能增量解析 JSON。
2. **批改开启思考模式**：V4.1 Flash 的思考模式可能提高批改质量，但思考 token 计入 10,000 上限。建议先用 harness 对比两种模式的得分稳定性和 token 消耗，再决定。
3. **每周自动诊断**：每周第一次打开时提示“生成本周诊断”，结果存本机，避免重复花费。
4. **个人文章的理解题与生词讲解**：导入的文章已有分类，可以用 `story` 的题目格式为它们出题。需要把文章片段发给服务商，应在导入界面单独开关。
5. **用低峰时段预生成讲解**：夜间为第二天到期的薄弱词批量生成讲解并缓存。DeepSeek 若仍有低峰价格可以省钱，但会生成一些用不到的内容，建议设上限。
6. **缺失英文简义的草稿**：词库中 333 个词缺开放英文简义。AI 可以生成标为 `provisional` 的草稿供你审核，但不能直接写入正式字段（`LICENSES_AND_RIGHTS.md` 的规则）。
