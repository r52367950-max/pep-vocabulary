## 性能与界面

阅读匹配从每次扫描完整词库改为按不可变词库数组复用 WeakMap 索引，保留首个同名词条、原文词序及 60 条结果上限。60 篇文章的结果逐篇与基线一致；每样本 240 次匹配，4 次预热，9 次取中位数，Node v24.19.0，同进程无网络：116.994 ms → 31.158 ms，耗时下降 73.4%。这是暖索引本地微基准，包含文章分词；不含冷启动建索引、网络、模型服务和物理 iPad 计时。可复测：`node --import ./tests/register.mjs scripts/benchmark-reading-lookup.mjs 0b8610b`。

插画缓存保留 48 个条目上限，新增 1,200 万像素总预算并关闭替换/淘汰的位图；按 RGBA 像素估算约 48 MB，浏览器其他对象与原生管理开销另计。

阅读页增加可移除筛选标签、预计阅读时长（按 180 词/分钟估算）、统一元信息分隔线和结果播报，保留中文、暗色、44px 触控与减少动效支持。浏览器验收：1360×1000 桌面、1024×1366 iPad 视口、390×844 手机及手机暗色；筛选、移除标签和打开正文通过，无横向溢出或 pageerror。视口模拟使用 Chromium，不替代物理 iPad/Safari 验证。

## 保留的边界

1. 私有来源元数据已从当前文件和再生成流程移除；Git 历史仍保留旧版本。历史清理涉及重写仓库，需另行决定。
2. 未取得 ID 的不确定 Live 创建继续占用单会话租约，需管理员在服务商核查并确认终止后处理。已知 ID 会话继续使用既有耐久关闭机制。
3. 真实服务商、付费调用、物理 iPad/Safari 和生产用户数据写入未在本次测试中执行；生产权限与表结构只做读取核对。
4. 旧页面缺少新前置条件时会被拒绝，重新加载后使用当前客户端；学习备份 schema 与稳定词条 ID 均保持。
