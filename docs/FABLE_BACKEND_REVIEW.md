## 本次采用的设计

沿用「模型生成 → 校验工具请求 → 只读执行 → 回传结果」的小循环，保持系统前缀稳定、对话只追加。工具的 schema、参数校验和宿主实现集中在 [toolbox.ts](../lib/assistant/toolbox.ts)，每轮模型调用仍走现有 `complete()` 的出站策略、额度预留与结算。

从交接方案吸收批量核词、屈折词形候选、册名与单元筛选：`lookup_words` 每次最多八个词，精确词头与可能词形明确区分；`search_lexicon` 支持教材、单元、前缀和中文释义。词条证据仅取自正式发布词库。计算、材料阅读、文本统计继续使用有界工具；统计可引用已选材料索引，省去模型重复输出全文。

运行边界保留当前实现的三次模型生成、六次工具调用、每批三个工具与 300 秒运行期限。词库按需加载，同一请求内重复调用复用结果；每次后续生成及最终返回前检查学习记忆版本。取消或超时会终止只读依赖的等待，已发生的模型费用完整结算。模型返回截断时在工具执行前停止。最终学习按钮仍须通过已验证词条 ID 校验。

## 原生工具传输的复核

交接包 `core.ts` 已实现 Chat Completions 的流式分片合并、非流式 `tool_calls`，以及 Responses 的 `function_call` / `function_call_output` 转换；schema 与工具参数也进入用量估计。这些适配思路可复用。本轮线上采用现有 JSON 工具协议，继续兼容当前服务商。

直接接入上传版存在以下明确缺口：

| 上传位置 | 观察到的行为 | 当前处理 |
| --- | --- | --- |
| `core.ts:1127`、`:347` | Responses 只保留文字和函数调用，丢弃 reasoning items；请求设置 `store: false`，没有请求及回放 encrypted reasoning | 原生适配须完整保留本轮服务端 reasoning items 再接入。OpenAI [推理模型指引](https://developers.openai.com/api/docs/guides/reasoning)要求函数调用后回传 reasoning items；[Responses 迁移说明](https://developers.openai.com/api/docs/guides/migrate-to-responses)说明无存储模式的 encrypted reasoning |
| `harness/loop.ts:75` | 中间回合即使标记 `finishReason: length` 仍可执行工具；只在服务端得到最终结果后检查截断 | 每次模型返回均先检查截断，再解析及执行工具 |
| `server.ts:544–550` | 根据通用 `provider_rejected_request` 重试无工具生成；按 base URL 与模型在整个 Worker 实例禁用工具；重试另起 300 秒期限 | 无自动付费重试，无跨账号能力缓存；单一运行期限 |
| `server.ts:524`、`:555` | 只在全部生成完成后复核学习记忆，后续回合会继续携带原有上下文 | 每次后续出站前及最终返回前复核 |
| `core.ts:1050` | 调用 ID 可为空并直接截断到 128 字符，循环未拒绝重复 ID | 整批 ID、参数、数量校验后执行，重复 ID 拒绝 |

上传版的四次模型生成与每步四工具允许最多十二次工具执行；本次采用的三次／六次限制降低最坏情况的请求量。未运行真实付费模型测试，不据模拟响应声称已验证服务商线上原生工具兼容性。

## Python 子集的隔离验证

上传解释器采用自建语法树，没有使用宿主 `eval`、`Function` 或开放网络。不过运行预算在实际输入下失效，因此本轮使用确定性工具箱，上传解释器不进入 Worker。

| 输入或位置 | 本次观察 |
| --- | --- |
| `[] * 10**12`，上传 `python.ts:881–885` | 空列表令预估长度与扣减步数均为零，内部重复循环持续运行。独立子进程设置 64 MB 堆上限，并在三秒截止后被终止（退出 137）；未返回解释器预算错误 |
| `s = 'a' * 5000; ''.join([s] * 5000)`，`:929` | 最终报字符超限，但检查发生在原生 join 分配之后；隔离测试堆用量约增加 25.1 MB，超过声明的一百万内存单元预算意图 |
| `d = {'score': None}; d.get('score', 0)`，约 `:973` | 上传实现返回 `0`；CPython 返回 `None`，空值被误作缺失键 |
| `round(2.25, 1), round(-2.25, 1)`，约 `:1029` | 上传实现返回 `2.3, -2.3`；CPython 返回 `2.2, -2.2` |

以上为隔离复现与代码检查结果；未执行更大内存样例。若后续需要通用 Python，应使用具备进程隔离和宿主资源限制的执行服务，并单独明确可读材料与网络范围。

## 前端接线与独立复核

工具执行摘要接入现有对话入口，保留固定工具名、成功状态与缓存命中三项信息；参数、来源文字、任意展示标签不进入摘要或历史。界面显示「已查词库」「已计算」等实际结果，失败工具明确显示未完成，直接回答不增加工具记录。返回和历史加载共用白名单投影；临时对话仍不持久化。

对话列表关闭时不挂载；打开时复用已保存对话与非活动草稿的派生结果。活动输入框打字不重算列表，非活动草稿变化、切换会话和账户重置均使相关缓存更新。少于六段对话时隐藏搜索，触屏打开列表不自动弹出键盘，搜索框单独约束 flex 布局。

独立复核额外串联真实发布词库的 `lookup_words`、两轮 harness、词条按钮校验及固定摘要，验证 `studies` 为待语境核对的词形候选、`__proto__` 作为普通未收录文本处理。另验证活动草稿缓存复用、非活动草稿更新与账户替换后的列表刷新，均通过。性能数字见本次验证报告，上传包中的旧基线不作为本次测量结果。
