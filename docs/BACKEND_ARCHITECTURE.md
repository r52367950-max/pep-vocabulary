# 词迹后端与数据架构

本文对应当前代码，区分已经实现的行为与后续方案。应用采用本地优先结构：离线完成学习，浏览器保存学习记录，用户按需开启云端备份和 AI。

## 已实现的数据边界

| 数据 | 保存位置 | 更新方式 |
| --- | --- | --- |
| 候选词库索引、词条详情 | 发布时生成的静态 JSON；浏览器缓存 | 随应用发布，详情按分片加载 |
| 词卡、六项技能状态、FSRS 状态 | IndexedDB `cards` | 完成复习后与事件一起提交 |
| 原始答题、提示次数、用时、调度前后状态、撤销记录 | IndexedDB `events` | 每次操作追加事件 |
| 学习偏好、列表、同步元数据 | IndexedDB / 客户端设置 | 本机保存；备份不包含服务器密钥 |
| 个人导入文章 | 独立 IndexedDB `pep-vocab-personal-readings` | 逐篇保存与导出 Markdown；不进入学习快照 |
| 作文、版本与批改 | IndexedDB `writings`（数据库版本 4） | 草稿自动保存；进入 JSON 备份与云端快照（schema 1.2.0） |
| AI 回答缓存 | 独立 IndexedDB `pep-vocab-ai-cache` | 按任务与输入缓存；可在设置中清空；不进入备份 |
| 可选云端学习备份 | D1 `sync_states` | 每个身份一份完整快照，以 revision 比较并更新；上传前仅查询元数据 |
| AI 服务商、模型、密钥密文 | D1 `ai_configs` | 同源设置请求；密钥仅在服务器解密 |
| AI 调用计数与 token 用量 | D1 `ai_rate_limits` | SQL 原子递增；请求按分钟与 UTC 日，token 按北京时间日 |
| AI 预算与输出上限 | D1 `ai_preferences` | 设置页与加密配置一并原子保存；配置或预算读取失败时拒绝生成 |

核心练习不依赖 AI 或 D1。模型失败、未配置密钥或云端不可用，不应阻断本地复习。系统朗读取决于设备语音引擎；没有捆绑真人录音。

### 本地事务与导入

- 复习必须同时写入词卡和事件，任一操作失败则整个事务回滚；写入前核对卡片是否仍是计算时读取的状态，防止两个页面相互覆盖。
- 撤销核对原复习事件、词条和调度前后快照。撤销首次学习会删除原先不存在的卡片，保留审计事件。
- 收藏、笔记从事务内重新读取词卡，仅合并相关字段，保留期间发生的复习更新。
- 导出在一个只读事务中读取各表。导入先完整校验，再在一个事务中替换；拒绝重复 ID、无效日期、损坏的调度状态、无效事件指标和不一致的撤销引用。复习链按递增 repetitions 核对前后状态与当前词卡，允许旧备份从已复习的基线开始；同一调度状态的学习分类须一致，保留 `paused` 暂停例外。撤销分支、笔记和收藏保留，时间相同或回拨不改变链的判断。已有矛盾历史会明确拒绝，不能通过静默删除事件修复。
- 支持用户数据 `1.0.0 → 1.1.0` 迁移。当前记录数量上限为词卡 / 列表各 20,000、事件 100,000、设置 1 条。文件导入仍应由界面在解析前限制文件体积。
- 本机数据库是这个浏览器配置文件的数据，并非独立的多账号数据库。共享设备需要明确处理本地归属；不能把服务端按身份隔离等同于浏览器数据隔离。
- 卡片、事件、设置首次加载使用一个只读事务；设置/元数据的跨页通知仅刷新相关表。设置修改在一个写事务内合并，避免不同页面的无关字段互相覆盖。
- 作文创建只允许新 ID；更新在一个读写事务中比较完整旧快照。并发修改和删除后的迟到写入被拒绝，编辑框保留未保存文字。备份要求至少一个作文版本，并验证批改的嵌套结构和六项技能字段。
- 恢复与清空会在事务内更换本机数据批次，并通知其他页面。作答、设置、笔记、作文、云端关联和替换确认在使用时核对原批次；旧页面不能复活已清空的数据。旧版数据库客户端需要刷新。未保存的作文与笔记保留在编辑框中，笔记保存失败后可复制或明确放弃关闭。
- 活跃复习按 UTC 时间值排序，同时间以事件 ID 确定顺序；随机 ID 的数据库读取顺序不再影响近期错题、诊断与写作推荐。正常追加保持常数时间，迟到事件按序插入，原始审计记录保留。
- 每道已展示的题目保持固定，造句或跨页更新不会更换其判分和记录字段。FSRS 计算时间不早于上一调度时刻，真实作答时间仍写入事件；当前数据批次的会话可在时钟回拨后继续推进和恢复。导入拒绝不可调度的状态，生成后再次检查词卡，避免日期或计数溢出进入数据库。

## 当前云端接口

### `GET /api/sync`

`GET /api/sync?metadata=1` 只选择和返回 schema、revision 和时间，不读取 payload 列；上传预检使用此模式。普通 GET 和下载恢复仍返回完整快照，身份隔离和 revision 比较规则保持一致。


成功返回：

```json
{
  "identity": "由受信任站点身份导出的稳定标识",
  "state": {
    "schemaVersion": "1.1.0",
    "payload": "完整备份的 JSON 字符串",
    "revision": 12,
    "clientUpdatedAt": "客户端提供的时间",
    "serverUpdatedAt": "数据库提交时间"
  }
}
```

没有远端快照时 `state` 为 `null`。响应不暴露整条数据库记录；身份标识用于把客户端 revision 绑定到读取时的账号。它是邮箱规范化后的 SHA-256，不应被当作无法推断身份的匿名化措施，也不是登录凭据。

### `POST /api/sync`

请求字段：`schemaVersion`、`payload`、`clientUpdatedAt`、`baseRevision`，以及新版客户端发送的 `expectedIdentity`。

- 身份始终由服务端认证上下文取得，客户端不能选择写入哪个用户。
- `expectedIdentity` 与当前身份不符时返回 `409 / identity-conflict`，解决读完 revision 后账号改变的问题。旧客户端暂时允许缺省此字段。
- `baseRevision = 0` 仅允许首次创建；已存在时拒绝覆盖。
- 更新通过一条带 `user_key + revision` 条件的 SQL 完成；两个设备从同一 revision 上传，最多一个成功，其余得到 `409 / revision-conflict`。
- 成功返回 `identity`、新 `revision` 和 `serverUpdatedAt`；客户端仅在成功后更新本地关联。
- 完整快照上限为 **5,000,000 字节**。请求解析同时限制字节数与读取时间，包含没有 Content-Length 的分块请求。
- `clientUpdatedAt` 仅作展示信息；不会用客户端时钟判定覆盖优先级。

当前是**手动整份快照备份 / 恢复**，尚未实现自动事件合并、实时同步或跨设备连续学习。界面遇到冲突应先导出本机副本，再让用户决定恢复哪份数据；不得自动使用最后写入者覆盖。

所有私有接口返回 `Cache-Control: no-store`；未登录返回 401，存储不可用返回不包含 SQL、绑定名称或内部错误的通用 503。

## 身份与 AI 请求安全

站点当前通过 `getChatGPTUser()` 读取托管网关注入的身份头。部署必须设置 `IDENTITY_TRUSTED_HOSTS`，值为经过该网关的精确域名列表（逗号分隔，不含协议、路径、端口或通配符）；缺失、空值或任一条目无效时拒绝所有身份，其他域名上的身份头也被忽略。本地测试同样显式配置测试域名，没有 localhost 自动放行。邮箱到稳定用户键的规则不变，因此已有云端记录仍归属于原账号。

**该部署仍依赖网关验证登录并移除外部伪造的同名头。** 域名列表不是身份签名；部署应禁用或保护绕过网关的 Worker / preview 地址，不能仅凭可伪造的 Host 证明请求来自网关。换用其他托管方式时，应先接入服务端验证的会话或签名令牌，再开放 D1 与 AI 私有接口。仓库中的本地测试不验证生产入口拓扑或网关行为。

AI 配置需要同源请求和设置操作头，保存与删除共用每身份每分钟 12 次、每天 100 次的原子限流；限流存储失败时关闭修改。前端只得到配置、是否存在密钥等信息；密钥不会通过配置 GET、普通用户备份或应用日志返回。配置保存携带数据库生成流程中的唯一写入标记，条件更新失败返回 409；配置与预算在同一 D1 batch 内提交。失败批次既不能恢复旧密钥，也不能覆盖胜出请求的预算。

新保存的密钥采用 **AES-GCM 加密版本 2**，每次使用随机 IV，附加验证数据同时包含账号标识、服务商和规范化后的目标 URL。只修改数据库中的目标地址，或把另一个账号的密文复制到当前行，解密会失败。旧版本 1 缺少账号 / 目标绑定，不能权威恢复其归属，因此运行时拒绝解密、使用或自动迁移；原配置行保留，设置界面提示用户重新输入密钥，成功保存后写成有作用域的新密文。配置 `AI_CONFIG_ENCRYPTION_KEYS` 与 `AI_CONFIG_ENCRYPTION_KEY_ACTIVE` 后，新密文使用带密钥编号的版本 3，作用域已绑定的 v2 / 旧活动密钥 v3 在下一次成功使用或保存时改用当前主密钥重新加密，轮换步骤见 [AI 部署说明](../AI_ASSISTANT_DEPLOYMENT.md)。

出站请求的现有约束：

- 只允许精确的管理员批准 HTTPS origin：默认官方 DeepSeek 与 OpenAI，自定义服务由 `AI_ALLOWED_PROVIDER_ORIGINS` 批准。配置、运行时加载与每次探测或生成请求共用策略，管理员负责信任该 origin 的 DNS 与实际目标；拒绝 URL 中的用户名、密码、查询串、片段和已知本机 / 私网 IP 或主机形式。
- 更换服务商或目标地址必须重新提供密钥，避免把保留的密钥发给新服务商。
- 不自动跟随重定向；连通性探测不发送密钥。
- 每次读取上游响应最多 300,000 字节，超时覆盖响应正文。异常、过大、超时响应会取消流，取消操作本身卡住也不会阻塞返回。
- 用户输入限长、词条 ID 受限；教材范围与核心义从服务器静态词库重新解析，模型输出只允许引用提供过的证据 ID。
- 请求可附带学习画像（错误作答、薄弱词、易混词、笔记、写作概况）。服务端逐字段校验与限长，只保留正式词库 ID，词头由服务端补上；画像作为数据放在固定系统提示之后，不能改变规则。
- 上游以流式读取，设置中的超时是无响应超时，单次最长 5 分钟；客户端取消传递给上游，缺少结束标志的断流不作为有效回答。输出上限 10,000 token（模型上限更低时取模型上限），剩余预算不足时自动降低本次输出上限。
- 兼容服务返回普通 JSON 时，正文分块同样重置无响应超时，整体时限不延长。官方已知仅支持默认温度的推理模型不发送 `temperature`；普通模型与自定义服务地址保留原参数行为，连接测试、助手和阅读分类共用 token 参数识别。
- 学习助手、阅读分类和连接测试共用预算入口：条件 UPSERT 原子预留估算输入及输出额度，成功后在一个 D1 batch 内结算三项计数，并固定记在请求开始日。未确认是否计费的失败请求保留预留至次日；结算失败不返还额度。输入估算不等于服务商实际分词，因此预算不是服务商账单的绝对上限。
- 设置中的今日预算占用包括未结算预留；成功结算取服务商 usage 与本地提示词、实际回答估算下限的较大值，低报或缺失不能绕过下限，采用下限时标记估算。读取预算失败不使用更宽松的默认值。
- 模型输出的 `origin` 和 `provenance` 由服务端重建；教材位置来自正式词库，模型自报的 citation 和核验状态不被采纳。词库没有教材原句跨度，所有回答都保持“教材引文未核验”。界面在正文前展示该状态，并从当前词库重建词条收录位置，旧缓存和备份内批改同样适用。页码检查不再用学生文章中的任意数字授权其他反馈；真实学生引文与局部日记引用可保留。文字模式检查只是辅助，不能证明任意自然语言引文或教学内容正确。

出站 origin 清单把目标选择权限定到站点管理员，阻断普通用户通过自有 DNS 主机选择任意目标的路径。它没有实现 DNS 解析后 IP 固定或独立出站网关；获批服务与其 DNS 的信任变化仍由管理员管理，需要连接地址级约束时采用受控出站代理。D1 学习快照不是端到端加密数据；这里的应用层加密专门保护 AI 密钥。

## 缓存与加载

AI 正式词库的 ID 映射随不可变发布索引复用；客户端 AI 缓存每次写入均在同一事务中裁剪至最多 600 条。学习诊断不使用永久结果缓存，以免空任务参数掩盖学习记录变化。

`loadLexicon()` 共享进行中的索引请求；`loadDetails()` 按清单数量映射分片，同一分片只下载一次，并允许失败后重试。静态词库与个人数据分开发布和存储。

构建插件对前端资源与词库内容计算发布指纹并注入 Service Worker 缓存名。安装时必须成功读取发布资源清单，并完整保存 shell 及清单资源；缺少脚本、资源被标记 no-store、缓存配额不足均导致安装失败，保留旧 Worker。运行期间可选资源缓存失败不会阻止在线请求。

API、登录 / 退出回调和 RSC 响应不进入离线缓存。新 Worker 等待旧页面关闭后接管，避免强制更换正在学习的页面。词条详情按使用下载；显式“下载离线词库”通过当前 Worker 逐批下载并确认所有分片已写入缓存，失败不显示完成。当前界面使用系统字体；实际资源以构建清单为准。浏览器仍可能在以后回收缓存。

## 增量事件同步参考方案：尚未实现

以下仅供收到相关功能请求时评估，不是当前任务或固定实施顺序。

整份快照会随答题历史增长，上传每次重复传输全部数据，也不能合并两台设备的学习。下一阶段可保留快照作为备份格式，新增以下协议。

| 实体 | 建议关键字段 | 作用 |
| --- | --- | --- |
| 本地待同步表 `outbox` | `eventId, deviceId, sequence, payload, payloadHash` | 与本地复习事务一起写入，避免离线操作漏传 |
| 云端事件 `learning_events` | `userKey + eventId, serverSequence, payloadHash, receivedAt` | 幂等接收、增量拉取、完整保留答题证据 |
| 云端词卡 `card_states` | `userKey + cardId, cardVersion, schedulerVersion, state` | 每张词卡独立处理并发 |
| 设备进度 `sync_devices` | `userKey + deviceId, acknowledgedSequence, pullCursor` | 确认上传、断点恢复和变更拉取 |
| 删除 / 重置事件 | `operationId, scope, generation` | 明确传播删除，防止另一设备把删除内容重新上传 |

建议一次推送上限先设为 100 条事件 / 256 KB，再通过真实负载调整。一个批次在 D1 中提交后才返回确认位置；断线重试相同 `eventId` 与哈希返回原结果，相同 ID 携带不同内容则拒绝。服务端从认证会话取得用户键，所有表与查询均按用户键隔离。拉取按服务端单调序号分页，不依赖设备时间排序。

同一词卡发生离线并发时，保留两份原始答题记录，显式返回词卡版本冲突，并基于服务器确认的版本重算调度。不能直接按时间覆盖 FSRS 快照；重算还必须固定调度器版本与随机行为，否则多个设备重放同一历史可能得到不同日期。笔记、收藏等独立字段可另设版本规则，不应覆盖复习状态。

推荐实施顺序：先完成本地 outbox 与重复提交测试，再接入云端幂等事件写入和游标拉取，最后实现并发词卡处理、删除传播和旧快照迁移。自动后台同步、多账号本地分区、端到端加密、管理与账号数据删除接口，都应作为独立功能交付并标明状态。
